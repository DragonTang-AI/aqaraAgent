# Favorite Speaker — independent adapter and card

User-requested extension to the existing six RN categories. Accept only an actual `Speaker` endpoint with declared MediaPlayback CurrentPlaybackState/TargetPlaybackState, Speaker.Volume or Boolean OnOff capability. A Hub with Speaker.Volume is not a Speaker device. Keep deviceId + endpointId identity, physical-device-first names and the shared RN-compatible metadata selection contract. Ordinary generation requires no upstream repository.

## Verified protocol snapshot

Reviewed against local Aqara spec definitions and the Studio public trait execute/read contract on 2026-10-16. `MediaPlayback.CurrentPlaybackState`: Playing 0, Paused 1, Stopped 2, Buffering 3, FastForwarding 4, Rewinding 5. Writable `MediaPlayback.TargetPlaybackState`: Play 0, Pause 1, Previous 6, Next 7. Enable only values actually present in returned supportedValues, preserving their raw string/number type for Enum parameters and numeric values for Integer/Float/Number parameters; a numeric parameter with explicit bounds may use these verified codes within its actual range. Do not infer enum meaning from translated labels or invent unsupported values.

Volume is the real numeric `Speaker.Volume`, with explicit min/max, step and unit. Preserve Float/Integer values and reject invalid/out-of-range/off-step writes. OnOff is an optional actual writable Bool OnOff point on this same endpoint; it is not mandatory in the Speaker specification. Never substitute Mute or Pause for power. A confirmed OnOff=false takes precedence over an older playback reading: show Off and disable transport/volume while retaining the real power-on affordance. Hide unavailable operations; unknown playback state must not pretend to be paused/playing. An actual current-state reading selects the play/pause affordance; unknown state may expose explicit supported Play and Pause separately. Read-only endpoints remain selectable and retain native plugin entry.

`MediaPlaybackCommand` plays specified media and has parameter fields; it is not a generic next/previous command and must not be fabricated as a zero-field shortcut. This release uses exact declared trait writes; other command-only models remain read-only for unsupported operations until a verified contract is supplied.

## Isolation and UI

`favorite-speaker.js` owns schema inspection, allowed values, readback normalization and the dedicated card. The ordinary favorite renderer delegates only Speaker items. Use `.fd-speaker-*` styles and existing semantic theme tokens, with no fixed theme palette, PNG, album cover or invented track title. Keep ordinary cards 173×126 at 390px. Speaker spans both columns at 358px width, with natural content height, minimum 126px, 16px radius/padding and 12px vertical gaps. Do not reserve two grid rows or a fixed 264px height. Use a 44px header, a 56px transport row only when supported, and a 44px volume row only when writable: transport-only is about 144px, volume-only 132px, full controls 200px, and read-only at least 126px (content/localization may grow). Do not stretch transport to fill spare height. Keep previous/next at 44px, play/pause at 52px with a 26px glyph; unknown playback may show both supported actions without overflow at 320px. Header uses a 40px vector icon, real name and room/state; power has a 44px target. Transport controls have 44px targets, and volume has a 44px slider hit area and visible border/focus/thumb in light/dark themes and narrow widths. Every visible action has a localized accessible name. Missing features do not produce fake controls or requests.

## Transactions and lifecycle

Use the existing favorite per-device transaction/version lock, scope guards, write enablement and offline/stale/cache protections. Validate the action against the latest canonical Speaker definition, not a descriptor supplied by the UI. One trait execute per action, followed by at most one grouped, delayed trait-read request for this endpoint's readable Speaker points. A nonempty failure array or malformed execute response is a failure. Only matching fresh readback mutates confirmed values. Acknowledgement is not physical playback/track completion. Play/pause checks CurrentPlaybackState; previous/next is acknowledged/observed without claiming a track change. Missing/malformed readback retains the last confirmed state and reports unconfirmed. No optimistic state, full scan, recursive retries or polling.

Slider input updates only a local draft; commit once on change/release, not per input event. Cancel/blur restores confirmed presentation. While a request is pending disable only this card's controls; keep its DOM and other cards stable. Plugin return follows the existing visibility/selected-refresh contract. Never change camera, rich space cards, Space control or native bridge behavior. Preview playback simulation belongs only in preview fixtures/host, never production runtime.

## Validation

Run Speaker smoke/browser gates covering full, partial, unsupported, read-only, unknown, offline, failed/malformed response, typed Float/enum values, bounds/step rejection, no-op render, one-write/one-read budget, held old responses, slider event bursts and capability revocation. Check 390/320 widths and light/dark themes, mixed ordinary/Speaker layouts, no overflow, real names, plugin entry and selector save/remove. Keep screenshots outside deliverables; never install dependencies or browsers automatically. Real Speaker and Safari acceptance remains with the user's App build.

## Split playback and volume endpoints

Keep separate favorite records/cards and exact `(deviceId, endpointId, functionCode, traitCode)` routes when one physical Speaker exposes playback and volume on different endpoints. Do not merge by name or copy capabilities/status between endpoints. Both cards retain the physical name and real room; distinguish a volume-only endpoint with its actual volume/unit (or the localized Volume label if unavailable), not a missing-playback “Unknown” status. Retain Unknown when a declared playback state is invalid. Pending confirmation uses the existing status line so issuing a write does not add a footer or change card height. Missing/read-only/stale hints remain truthful. Use a light slider thumb with a semantic contrasting border, retaining the 44px input target and one-change write budget.

Validate same-device playback-only and volume-only endpoints alongside a full Speaker: real selector/save, independent pause/next versus volume coordinates and grouped reads, unchanged card nodes/height while pending, light/dark and 390/320 widths, unknown playback with both supported actions, no fake volume/power controls, and mixed ordinary-card geometry. Keep fixtures in preview only.
