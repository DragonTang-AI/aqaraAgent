# Devices and Smart directory contract

Design snapshot: Aqara Life, file `7lHXkR3FiEI2MlBBSCa0h7`, section `20564:9469` (设备 tab & 智能 tab). The rules below are bundled so ordinary generation needs neither Figma access nor an application checkout. Apply to optional Devices/Smart pages only; Home rich/favorite cards, Space control, camera and tab-combination contracts retain their own geometry and behavior. Themes change semantic paint, not this structure.

## Pages and data

- Devices: leading Mine menu using the existing native action, large 34px/44px title and 13px/18px truthful count; 44px search entry alongside a 44px filter target. No duplicate Home/Studio heading. Show separate space sections keyed by actual space ID; unassigned is last. Same-named spaces remain separate. No redundant space-select dropdown.
- Individual device rows have a 72px minimum height, 16px padding/radius, 40px icon, 12px gaps, 16px/24px regular device name and 16px chevron. Grow for accessibility/long names rather than clipping controls. API-owned device imagery may be dynamic; use existing local pure SVG category/common fallbacks when no image is returned. Never bundle Figma sample devices or PNGs.
- `state` accepts Boolean, 0/1 or their string forms only. False shows an offline badge and dims row content to 40%; unknown is explicitly labeled, never treated as offline or online. Offline rows still open the native device plugin. Plugin navigation keeps the existing capability/accepted-ack contract.
- Smart: same page-title and statistics hierarchy, followed by Scenes / Automations segmented tabs. Exactly one segment panel is visible. Preserve separate panel state; the segment sticks at the CSS safe-area top on upward scroll. A CSS sticky layout and bounded viewport minimum height avoid continuous scroll measurement. A scrolled segment switch restores the target position with the header still collapsed; switching before collapse retains the current offset.
- Scenes: compact individual 72px-minimum rows, name and optional real space subtitle, trailing play action. Disabled/unknown scenes remain visible but cannot execute. Automations: same row structure with a 64×28 visual switch inside a ≥44px touch target. Preserve exact ID, known-status/write guards, one write per tap, no automatic retry, and successIds/failedItems handling.
- Only expose implemented native actions. Figma's device-add button has no maintained H5 host capability, so do not add an inert or invented add-device route. Existing Mine action is reusable on the optional pages. Bottom navigation keeps the existing configurable count and glass/theme contract.

## Existing OpenAPI only

Use the shared Life bridge with `source: studio`. Devices and automations are lazy bounded-page directory requests (200 per page, explicit load more); never copy RN's full-catalog preload loop. Include real space assignments. Retain previous rows on next-page failure, retry the same page, deduplicate real identities, and preserve API totalCount. Without a total, say Loaded N rather than presenting a loaded-page count as a complete total. Scene total is the returned deduplicated scene identity count.

- Devices: GET `/devices`, `deviceName`, optional `state:false`, optional exact `deviceTypesList` plus `deviceTypesMatchMode:or`, `pageNum`, `pageSize`. Filters intersect before server pagination/totalCount. Do not send a UI category/name as a device type.
- Device type choices are exact nonempty strings from returned `deviceTypesList`, accumulated across loaded pages. Keep unknown type labels verbatim; only localize an explicit known type mapping. Figma's nine product categories are not a published exhaustive mapping of protocol device types. Never invent that mapping or fetch every device merely to populate choices. If more pages remain, explain that further loaded devices may add types. Real shades and unknown future types remain selectable. Product-wide category discovery can replace this policy only with a verified taxonomy/options API.
- Automations: GET `/automations`, `automationName`, `includeSpace:true`, existing order/page parameters. Scenes: GET `/scenes`, `pageNum`, `pageSize:200`, `needChildren:true`; reuse RN-compatible normalization and execution in [favorite-scenes-contract.md](favorite-scenes-contract.md).
- **User-confirmed API limitation:** no reliable public scene/automation product-type filter or type-association field is available in this snapshot. Hide the Smart type-filter entry until a verified existing API supports it; never guess from names, definitionType, Home capability categories or hidden device reads. Figma's future space filter is also not part of this release.

## Filter transaction

Device modal is a centered 358px phone-width (responsive up to 420px) surface with 24px corners, dim backdrop and independently scrollable content within safe areas. Status offers All/Offline; Type offers All plus real known options. Each group is single-select; groups intersect. Targets remain ≥44px even when the visual Figma chips are 32px. Draft choices never send requests. Backdrop/Escape closes and discards drafts. Apply commits, closes, resets to page 1 and refreshes only if changed. Reset restores both All values, closes, and reloads if changed. Highlight entry only while a committed filter is non-All. Refresh/search/pagination retain committed filters. Restore focus/scroll; trap modal keyboard focus and exclude it from pull refresh.

## Search lifecycle and budgets

Search reuses the current input and directory renderer in an isolated full-page search state. On entry the field moves toward the top safe-area band, page heading/segments/bottom navigation are hidden, keyboard can focus immediately, and blank input shows no result list. A small inner clear empties input; an outer close/Escape exits and restores the pre-search records, filters, count and document position without another query. Preserve native plugin navigation, scene actions and automation switches within search results. A write in search must update the restored directory state too. Dismiss the keyboard on results drag; keep toolbar sticky and resize only on visualViewport resize so the keyboard cannot cover the close control.

Devices/automations use 300ms trailing server name search. Enter submits, IME composition never submits prematurely, identical trimmed queries deduplicate, and clear leaves the blank search page without a request. One read in flight per list; queue only the latest reset, use revision guards to discard old success/errors, and preserve the query/filters for next-page requests. Closing an in-flight search invalidates its response; it must not overwrite restored directory state. A failure has a retry, never an empty-success illustration. Do not refetch spaces on keystrokes. Scenes use case-insensitive local name matching over the existing complete scene response; do not invent a name query parameter or preload devices/automation details.

The search field is a single composite capsule containing icon, input and clear control. Scope `appearance:none`, no inner outline and no inner box-shadow to `.directory-search-input`, including its focused state, so WebKit and shared generic input focus rules cannot draw a second pill around just the text region. Preserve the 44px field and 16px text. Touch focus uses the text caret; fine-pointer desktop focus outlines the whole search wrapper with the theme focus token. Do not change global focus styles or other form/slider controls. Run `scripts/profile_search_focus.mjs <runtime>` to verify all three search scopes with mobile touch and desktop Tab-key focus in light and dark modes.

## Scene actions and refresh

Scene play follows [favorite-scenes-contract.md](favorite-scenes-contract.md): one `/scenes/execute` for sceneId, otherwise one legacy manual-pair write; no fallback after failure. Pending shows the shared local SVG spinner and locks that identity; request success/failure shows a check/error for 2 seconds; failure also shows a localized toast. Success acknowledges the request, not physical execution completion. No collection refresh/readback/polling after play. Patch only the affected action. Automation status writes patch the existing switch and any linked scene gates in place; preserve node identity and pending guards, including after returning from search. Keep Home's existing deferred availability revalidation.

Reuse the single Home/Devices/Smart pull-refresh gesture owner and its request callbacks. Never add a page-specific touch recognizer. Every page reveals the same top zone by moving the dedicated content wrapper while the shell and bottom nav stay stable. Search, filters, switches and segmented tabs own their gestures. Verify nonzero safe areas, list-text origins, hold/reset and no ghost clicks. A deliberate Smart refresh updates both segment datasets independently; a warm segment/tab switch does not request data.
