## Home and selection page

- By default Home shows Favorite scenes below the existing AI entry and above devices; explicit `homeModuleOrder` overrides that position. For newly generated configs, first-use view-only defaults follow [daily-use-role-contract.md](daily-use-role-contract.md): 1–6 scenes all, >6 six confirmed IDs or a selection prompt. Existing records, including empty, always win. Old configs without favoriteSceneDefaults retain the prior empty default. Both the + button and empty panel open selection. Smart still shows its full real scene/automation lists; favorites do not replace that module.
- Use two equal columns and 12px gaps. The unscoped base has at least 56px scene height, 16px corner radius, 16px visual padding including border, and 16px/24px one-line name typography; role presentation may increase height, change padding and allow two lines while retaining the complete accessible label and reserved right 20px feedback slot. At a 358px content width, each card is 173px. Width responds to the shared page container; do not hardcode 173px at other widths. Device S/M/L/XL geometry, typography and controls remain untouched.
- Favorite cards use restrained theme-aware tint over a stable surface. Do not retain the old horizontal oversized colorful scene tiles. Apple/Aqara/custom themes share this layout and adapt paint, including dark text contrast. The original plus SVG is inverted in dark mode; the confirmation button has independent semantic fill/text slots so its label remains readable without changing other controls. The success indicator is a web check-circle adaptation; do not embed the proprietary SF font or claim native SF Symbols rendering.
- Every favorite scene card has a decorative symbol selected from the same household concept map. Unscoped/adult/senior cards retain original local vectors on a shared 24px grid with rounded strokes, theme-derived accents and subtle tinted backing; senior may use a slightly heavier/larger symbol. Child cards render the original, self-contained scene art from `assets/child-scene-art.svg` in a consistent softly dimensional icon slot, with a neutral sparkle symbol for unknown names. Inline the one SVG sprite only for child output, then reference its symbols from cards; do not duplicate SVG paths per card, fetch remote icons or ship the source sprite as a second runtime file. Keep art outside the real title, status slot, accessible action label and request payload. Match real names to concepts such as arrival, departure, morning, night, reading, movie, dining, play, lighting, shading and climate. A scene-name heuristic is decoration only: it must not change the displayed name, identity, category, availability, execution route or request payload. Child-only card paint and height may adapt to the approved visual proposal; the shared two-column layout and other roles remain unchanged.
- Selection is a secondary full-screen dialog/page above Home: a 44px back button with the same 24px chevron/currentColor, 2px stroke and 16px horizontal header inset (12px at widths up to 350px) as the Favorite devices selector, localized accessible Back label, centered title, scrollable real scene rows with check states, bottom Done (count/10), safe-area padding. The main app becomes inert while open; trap keyboard focus and handle Escape. The overlay owns scrolling; Home refresh gestures cannot start inside it. Restore focus and Home scroll on close. Keep existing Tab and other modules unchanged underneath.
- Draft preselects saved identities. Toggle rows to add/remove; allow 0–10. Attempting an eleventh selection leaves the draft unchanged and shows maximum-count Toast. Back/Escape discards changes. Done saves atomically, closes to Home and updates the favorite component without rebuilding device cards or rereading every device. Saving zero is valid. Selection does not execute, enable, disable, create or delete Studio scenes.

## Real data and identities

Home, Smart and selection share `StudioRuntime.listScenes()`: `GET /open/api/v1/scenes` with `pageNum:1`, `pageSize:200`, `needChildren:true`. This aligns with the current RN scene API, rather than the older manual-trigger catalog. Keep automation queries/switches on their existing separate APIs. Read pages sequentially, at most 100; stop on reached positive totalCount, absent pagination metadata, empty/short flattened page (<200), or no new IDs. As in RN, absent/invalid totalCount falls back to the parsed page length; do not invent additional pages when that fallback reaches total. Keep P0 in-flight sharing and the scoped 30-second collection cache; no duplicate query just to enter a Tab or selector. Search scene names locally over this loaded catalog; no invented server keyword parameter.

Accepted envelope data: an array; the first array under `data`, `list`, `scenes`, `records`, `items`, `children`; or a scene-like object. Recursively collect `children` through depth 8. Preserve source order and first occurrence of each identity across children/pages. Reject malformed non-list responses rather than treating transport failure as an empty catalog.

Normalize fields exactly: string/number IDs become strings; identity `sceneId` → `id` → nonempty `automationId#triggerNodeId` components. Name priority `name` → `sceneName` → `triggerName` → `automationName`. Preserve optional numeric `createTime` and string `definitionType`. Missing/null enabled defaults true; Boolean unchanged, number nonzero true, string only `"true"`/`"1"` true. Preserve genuine optional `space` only when returned; RN does not depend on it, so never infer a room. Generic `id` supports display/selection identity, not an executable sceneId.

Disabled favorites remain selectable with execution blocked. Save only returned identity coordinates, resolve display/status from current API data. Missing favorites stay unavailable/removable; never infer deletion from a partial/failed response. Initially render at most 200 selection rows and grow by 200; this UI window is separate from API paging. Failed reads show retry with Done disabled.

Use [favorite-metadata-contract.md](favorite-metadata-contract.md) for persistence. Restore ordered `favoriteScenes` sceneId strings through the shared metadata repository and resolve names/status from the existing catalog. Old local manual-pair records are not automatically imported or uploaded; only real returned sceneId values may enter new metadata. Existing execution fallback for a real scene's manual coordinates remains unchanged.

The metadata read is scoped to a confirmed Studio DID from the native connection-status bridge. While that identity is unavailable, show a localized Studio-unavailable state and disable selection; do not leave the card saying scenes are still loading when no request can start. A later valid status resumes the normal metadata read, and an actual read failure keeps its retry state.

## Server persistence and preview isolation

`favorite-scenes.js` keeps selection/execution UI independent; `favorite-metadata.js` shares reads and serial saves with Favorite devices. Preserve layouts and drafts. Save success closes the editor and updates Home; failure retains the draft. Back/Escape never write. Current native identity owns the server request context; pathname/root-space IDs and legacy scope flags never partition service records. No runtime localStorage favorite fallback. The PC preview simulates the same API in isolated iframe memory; reset starts a new simulated session. App exports exclude that simulation.

## Execution feedback

If the returned scene has a nonempty trimmed `sceneId`, send `POST /open/api/v1/scenes/execute` with only `{sceneId}`. Otherwise require both trimmed `automationId` and `triggerNodeId` and send the legacy `POST /open/api/v1/automations/manual-triggers/execute` with only that pair. Never substitute generic `id` for sceneId. A failed native-scene write must not fall back to a second legacy write. One user click produces one write with no automatic retry or device readback. A pending operation blocks repeats of that scene identity without blocking unrelated scenes. Existing bridge envelope/business errors remain failures.

While pending, render the downloaded loading asset in the fixed feedback slot, with an accessible busy state. A successful request displays success; it does not prove every target device completed the action. Success/failure indicator clears after 2000ms from settlement. Failure also shows the localized generic operation-failure Toast (zh-CN: “操作失败，请重试”; zh-TW/en equivalents); do not expose a raw native/API error message or its language to the user. Keep the existing button/scene component mounted during execution; no collection rebuild or card/page movement. Cancel an old indicator timer before reexecution; stale completion/timeout from another scope or page lifecycle cannot update the current view. Persist no execution state.

Enabled cards give a clearly visible pressed scale of about 0.93 on touch/mouse; keyboard focus remains visible. Starting the existing single request gives only that card a one-shot, 320ms rebound up to about 1.035, then returns it to identity. A theme-colored surface wash sweeps once for about 780ms; if the request remains pending, the fixed-slot spinner and static state border continue without repeating the sweep. A successful response gives one short scale pulse up to about 1.03; failure nudges only that card by at most 5px and 0.7 degrees for about 360ms. Result surface tint settles in about 320ms. Preserve the existing 2-second result-icon window after settlement: stronger visual animation must not change API timing or claim physical device completion. No visible request-status sentence, bottom-edge progress line, looping card movement, grid movement or page shake. Animated transforms do not alter layout boxes or neighboring cards, and the card must return to identity at rest. Decorative light stays behind the real scene name and status icon and inside the card. Disabled/unavailable cards do not appear pressable. Reduced-motion settings retain static boundaries/icons without scale, nudge or sweeping wash. Apply this visual state language to unscoped, male, female, senior and child cards without changing their independent materials, dimensions, scene selection or execution behavior.

The loading indicator uses a bundled pure-vector `icon-loading.svg`: twelve rounded spokes at 20px geometry, animated by the existing CSS rotation. It is shared with Favorite devices and Space control. It contains no foreignObject, script, external URL or embedded raster data; do not restore the previous raster fallback. The plus and failure SVGs remain downloaded local resources at their intrinsic root geometry; no temporary Figma URLs are runtime dependencies. Do not relax production SVG safety gates.
