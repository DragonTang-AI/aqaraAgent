# Home module layout

## Intent and boundaries

An explicit user layout overrides module-position defaults in AI/scenes/devices/Space-control contracts, independently of theme, locale, tab count and device mode. With no instruction, use `overview,aiAssistant,favoriteScenes,devices,spaceControl`. When editing, preserve the existing complete `config.homeModuleOrder` unless asked to change it. For relative requests (e.g. scenes first, AI after overview), move only the named modules and retain other modules in prior relative order. Clarify contradictory constraints; do not invent a missing module or interpret ordering as hiding/duplicating one. Device-mode intent is resolved independently.

| ID | Module |
|---|---|
| overview | Household summary including its lighting/shade/climate entries |
| aiAssistant | AI entry and capability-derived suggestions |
| favoriteScenes | Favorite scene grid and add entry |
| devices | Space-based devices OR favorite devices, following homeDeviceMode |
| spaceControl | Space control summaries and room filter |

All five occur once in the complete config. `devices` moves both mutually exclusive containers as one block; only the chosen mode displays. Do not create separate order IDs for its two modes. Page navigation, Studio banner, notice/fatal messages, toasts, refresh indicator and secondary dialogs are not sortable modules; preserve their existing template positions. This feature does not add hide/drag-sort/personal layout persistence or change remote Studio settings.

## Generate and edit

```
node scripts/generate_h5.mjs --output <new-workspace> --with-preview --tabs home,devices,automation --home-device-mode favorites --home-module-order favoriteScenes,overview,aiAssistant,devices,spaceControl
```

The parameter accepts unique stable IDs separated by commas. Omitted IDs append in default order (e.g. `favoriteScenes` means scenes first, then the remaining default modules). Omission uses the default; empty/unknown/duplicate IDs fail before output creation. Store the normalized full array as `homeModuleOrder`, not translated labels. Natural-language relative instructions must be resolved by the agent into a complete array before generation so that their meaning is preserved.

For packages generated by the current template:

```
node scripts/configure_home_layout.mjs <runtime-directory> --order <complete-comma-separated-order>
node scripts/refresh_preview.mjs <workspace>
node scripts/validate_preview.mjs <workspace>
```

The configure helper updates config and complete marked HTML blocks together, preserving other config values and runtime files. On a flat App package omit preview commands and use `validate_h5.mjs`. A legacy package without module boundaries needs a deliberate template migration preserving its custom content; the helper fails without modifying it. Never change config alone and claim the HTML is reordered. Export a new clean App directory from a validated workspace with `export_app.mjs`.

## Rendering invariants

Ordering happens at generation/edit time using `scripts/home-layout.mjs`, before first paint; ship no new runtime script and make no runtime DOM moves on load/refresh/theme/tab events. Move whole marked blocks with original IDs, handlers and internal markup intact, including overview category controls. Set `data-home-leading-module` from the normalized first ID; it removes the leading module’s extra outer margin and gives an overview moved lower a 24px outer gap. Default overview-first spacing and internal module/card sizes remain unchanged. Do not use CSS `order`, positive tabindex, cloning or separate preview markup: visual, DOM and keyboard/reading sequences must agree. Keep secondary-page focus and return anchors, camera nodes/lifecycle, card geometry, filters, API budgets, storage and visibility gates unchanged. Default and custom layouts use the same data and code. Module content can still change height through its existing data/anchor logic; sorting itself must cause no late movement.

## Verification

Run `smoke_test_home_layout.mjs` for all 120 complete permutations, default/partial/invalid inputs, device modes/tab variants, configure helper integrity, and config/HTML mismatch rejection. Run `profile_home_layout.mjs <workspace> --qa-output <external-dir> --playwright-module <existing-module> --browser <existing-browser>` on default and custom packages in both device modes. It verifies DCL/loaded/theme/locale/refresh order and node stability, visual positions, 320px overflow, AI entry, scene selection/execute, device selection or rich-grid presence, and shared overview details. Use existing browser/dependencies only; skip unavailable browser gates honestly without installation. Inspect screenshots outside deliverables. Also run `validate_h5`, `validate_preview`, `validate_aqara_style`, applicable runtime/Space/favorite smoke gates, and export validation. Real native/device acceptance stays with the user.
