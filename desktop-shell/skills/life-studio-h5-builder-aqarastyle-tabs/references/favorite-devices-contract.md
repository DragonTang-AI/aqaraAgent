## Model and persistence

Use the returned physical device ID plus integer endpoint ID as identity. Read endpoint `deviceType`, `EndpointLabel.EndpointName` and `EndpointLabel.EndpointRoom` from public definitions. Both the selector and Home cards use the actual physical device name from the device-list `deviceName` (the normalized `model.name`) first, matching RN. Only when that name is missing or whitespace-only may they fall back to a nonempty EndpointName/endpointName, then the localized Unnamed device label. Generic endpoint names such as 灯, 窗帘 or PowerSwitch must never override a real physical name. Do not synthesize endpoint suffixes on a real device title; multiple valid channels can share that title as in RN, while their identity, state and writes remain isolated by deviceId + endpointId. Never infer names from type/model/room. Explicit empty room means Unassigned; an absent room label can use the device’s returned room. Unknown nonempty room IDs stay unknown, not falsely unassigned. Room names come from real spaces. Never infer endpoints, traits, values or rooms from names.

Restore `favoriteDevices` through the shared repository in [favorite-metadata-contract.md](favorite-metadata-contract.md), matching RN `{did,endpointId:string}` records in current native request context. Users choose 0–10; explicit server empty stays empty; female missing-key view-only recommendations are the sole opt-in generated-role exception described in daily-use-role-contract.md. The local `storageScope` flags are legacy configuration and do not partition server favorites. Do not read, write or auto-upload old local selections. Unknown Studio identity disables editing; failed metadata reads offer retry without clearing confirmed choices. Preserve missing endpoints as removable unavailable cards. Save failures keep the draft open. Follow the explicitly accepted RN whole-map-save limitation in the shared contract.

## Shortcut and status rules

- Light/AC/power: AC includes returned `IRDevice` endpoints as in RN; classification alone never enables a write. Only a returned typed writable Boolean OnOff/Power/PowerState point. Render actual on/off; light brightness and AC current temperature use exact returned readable points/units. Percent conversion requires explicit definition bounds; no guessed scales.
- Curtain: only returned zero-field `AutoControl` under the endpoint’s actual curtain model/function. Figma defines stop during motion, otherwise reverse the previous motion. That behavior belongs to the command/device; H5 sends its actual coordinates with no fields. Never simulate it using target 0/100, StopMotion plus guessed direction, or fabricated command IDs. Show loading for 500ms and restore the stateless glyph; keep duplicate writes locked until the real request/reconciliation completes. Display actual current percentage when available.
- Lock/contact/presence: favorite-only RN-compatible display mapping: `ContactSensorState` true/1 means Open, false/0 Closed; `ContactDetected` has the inverse meaning, while `Open` is positive. Presence accepts explicit Boolean/0/1 and corresponding strings, never arbitrary truthiness. `LockState` 0 or 2 means Unlocked, 1 Locked; legacy Boolean Locked/LockStatus remains supported. Prefer canonical ContactSensorState/LockState when present. Unknown/malformed values are not locked/closed/occupied; preserve a returned display label or show Unknown, and hide an indeterminate/offline lock-state glyph. Text and glyph use the same resolved lock state. Figma does not supply a safe H5 unlock command mapping, so lock glyph is read-only and the card opens the native plugin. Never infer an unlock write.
- Offline action: Toast and zero requests. Missing exact capability: unavailable/read-only shortcut. Cache, refresh, unknown identity and pending conflicts gate writes.
- Each valid shortcut issues one public trait or command execute and at most one delayed targeted state-read pass. Require an empty failure array for accepted writes; malformed/failure responses are errors. Favorite shortcuts do not optimistically guess a state. Matching readback is silent; unconfirmed/mismatch is truthful. No full collection refresh, metadata write or recursive retry. Revision/identity guards discard stale UI updates.

Existing saved out-of-contract endpoints are retained as unavailable, read-only, removable entries, cannot be newly selected, and are not silently deleted by cancel or saving unrelated choices. This alignment changes candidate eligibility only; use the physical-device-first title rule above and retain the existing H5 endpoint rooms, geometry, local persistence, temperature semantics and real control transport. No device add/delete/configuration request occurs while choosing.

Reuse the existing overview/capability cache. Completing the full index is an explicit editor-open operation, coalesced with existing Space control index work; never add a second startup scan. Honor the maintained 5000-device ceiling with partial coverage when exceeded, mount only 200 selection rows initially and append by user action. Background indexing creates no hidden favorite cards. Keep card nodes stable for updates; scroll-lock, safe areas, focus restore/containment and gesture exclusions match other secondary pages. No default preselection from preview fixtures.

## Shared state and refresh (2026.10.15.2)

Favorite projection reads the shared canonical device entities also used by Space control; the supplement stores IDs, never a second copy of capabilities or online state. Definition reads capture a request sequence before dispatch. Commit only in the current Studio/load revision and if no newer device transaction has committed. Online/name/room summary versions additionally prevent an old catalog snapshot from replacing a newer summary. Accepted writes hold a per-device transaction lock and advance the entity version on completion, preventing an earlier definition result from rolling back confirmed readback. Preserve exact capability validation and the one-write/one-targeted-read budget.

Opening selection shows known endpoints immediately, then filters with the same `isCandidate` predicate as the selector before taking the first 200 candidate rows, and refreshes those candidates if their last validated read is older than 10 seconds. Existing shared index completion remains coalesced; no startup scan or polling. Room changes are local. Keep draft and row/card identity across unrelated/background updates; patch changed rows and preserve focused controls. Append beyond 200 explicitly. Confirm saves metadata through the shared query/update transaction; unchanged, reorder and removal-only commits issue zero device/entity reads; additions reuse the just-loaded shared snapshot and resolve only missing saved IDs. Never refresh the entire selected collection merely because Confirm was pressed. Full index coverage remains bounded at 5000.

Actual native return uses the optional `getCurrentPageVisibility` / `PageVisibilityChanged` contract in life-bridge-contract.md. ACK is not return. Consume one hidden-to-visible transition, deduplicate sequence numbers, and ignore theme/focus as refresh triggers. Old hosts may use a genuine document hidden-to-visible or BFCache transition; where WKWebView does not deliver one, plugin return auto-refresh requires the host capability. Do not invent support or add a theme workaround. Restore/foreground refresh has no timer polling.

Return refresh reads sequential catalog pages until selected IDs are found (5000 bound), then definitions for those physical IDs only (up to 10). Identical callers join one request; differing target sets serialize. A cancelled caller cannot mutate entity state or freshness; a valid caller joining cancelled work must retry. No waiting for unrelated whole-house definition indexing. Validate scope/cancellation before every commit, including failed and absent device handling. Only an exhausted authoritative catalog proves device absence; reaching a scan bound does not prove deletion.

Refresh silently while retaining last confirmed values and usable unrelated controls. No collection-wide loading label, card dimming, edit lock or spinner. On a valid read failure, preserve last confirmed values with localized “Needs update” marking, keep plugin entry, and block affected shortcuts until a successful read. Unknown connectivity is never online; definite offline uses explicit Bool/0/1/true/false parsing. A successful fresh definition replaces revoked endpoint capabilities. Scope changes discard old UI work. Retain card nodes, icons when unchanged, scroll and drafts; no repeated collection render callback during local selection changes.

Keep the Figma 24px curtain glyph as a centered local image in the existing 40px circle/44px hit target. No external CSS mask. Keep 500ms stateless feedback, real pending-command lock and exact AutoControl protocol. Typed Boolean and finite numeric readable projection stays isolated from rich-card readings.

Verification: run `smoke_test_favorite_devices.mjs`, `smoke_test_favorite_concurrency.mjs` and the favorite browser/freshness profiles. Cover held old response after a fresh commit, cancellation without freshness mutation, stale selector update, shared identical reads, zero-request unchanged/removal saves, stable editor drafts/card nodes, native event duplicates and no theme-triggered HTTP. Verify light/dark/file entry and the default space/camera regression. Native source syntax checks do not replace the user’s App build and live return test.

## Single-button curtain compatibility review (2026.10.15.4)
