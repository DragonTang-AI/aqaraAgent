Evaluate `/devices/capabilities/find` separately against real Studio response coverage, request size and LAN/cloud latency before adoption.

`StudioRuntime.spaceControlIndex()` reuses the existing overview catalog and definition/model cache. Space control adds no startup discovery/definition request stream. The current Home first-page request budget stays intact. For an index truncated by the normal overview budget, expose an explicit Load complete space data action. Do not silently label a partial index whole-house or enable bulk control until complete. A failed/partial index remains readable with unknown/missing state and disabled bulk writes. Room switches use the local projection without another HTTP request. No per-room redundant HTTP queries or unbounded per-device request fan-out.

## Exact controls and results

- Power: an actual writable Boolean OnOff/Power/PowerState on the relevant typed endpoint, with an exact model control ID. Never use the first Boolean metadata trait as a power switch.
- Curtain open/close: exact writable TargetPositionPercentage with a documented 0–100 range, 100/0 respectively. State counting uses readable CurrentPositionPercentage, not the target command or a name heuristic. Missing current percentage is unknown; it does not prevent an independently supported target command.
- Stop: only a real WindowCovering endpoint's WindowCovering.StopMotion command with zero declared fields. This is a separately reviewed, scoped projection (`spaceCommands`); it does not broaden generic safeCommandCodes or expose arbitrary commands on Home cards. Missing/field-bearing stop definitions are disabled. Never infer Stop from a ringtone/motor enum or send guessed coordinates.
- A group action reloads the current shared in-memory index and constructs an exact target plan immediately before dispatch from the chosen category/space. Skip offline/unsupported devices and report them separately from already-satisfied targets. Reject fake/stale point IDs or incomplete index. Lock the affected Home control keys during the operation; keep original Home cards mounted. Refresh revisions invalidate late results.
- Batch public trait/command writes in groups of40, serially; no automatic retry. Their success envelope contains an array of failed entries, not an array of successful values. Check full point identity for each failure; invalid/ambiguous failure data is not treated as global success. Partial successes and skips must not produce an all-success claim.
- Request success means accepted. Do one delayed targeted batched read pass (40 points each) for accepted traits and actual curtain positions; no whole-device/space refresh and no speculative optimistic group counts. Update only real returned values. Missing reads are unconfirmed; displayed counts do not turn into a fake all-on/all-off state. Preserve existing single-device controls and their reconciliation guards.
- Figma's control loading graphic is visible for500ms, independently of network duration. Restore the glyph after500ms; duplicate/conflicting actions remain guarded until the actual operation settles. Never fake an ACK at500ms. Keep indicators/operations scoped to the current view; stale completions cannot update another Studio refresh.

## State-aware batch targets

Lighting/climate on/off skips a target only when a real readable power point at the exact endpoint/function/trait has observed the requested Boolean within 30 seconds. Never suppress from optimistic control values, cached snapshots, unknown/missing/expired state, or a different endpoint. Store point observations separately from presentation state. Device trait/command writes invalidate observations for that device before dispatch, even on timeout/failure; scene execution invalidates all device observations. Valid exact targeted reads restore only requested readable points, guarded by load/scope/write versions. Fresh definitions replace observations; no extra discovery, pre-read, polling or per-device request is introduced.

Current position alone does not prove a curtain is stationary. No verified public motor-state mapping was found in the current contract, so shade open/close/stop remains conservative and sends to supported online targets even at 0/100. Do not infer motion from target position, names or undocumented enum values. A future reviewed motion adapter may suppress only when fresh actual position equals target and fresh motion is explicitly stationary; Stop can skip only with verified stationary state. Unknown/moving/expired shade state always sends.

All-satisfied batch actions remain enabled and show a localized already-on/off message without writes, readback, loading animation or device state changes. With offline/unsupported peers report both satisfied and skipped, without claiming all devices succeeded. Mixed plans report accepted, already-satisfied, failed and skipped counts separately; append unconfirmed readback counts. Existing serial batches of 40, no write retry, targeted reads of accepted targets and single-device/favorite controls retain their contracts. The same plan is used by overview, summary and detail entry points.
