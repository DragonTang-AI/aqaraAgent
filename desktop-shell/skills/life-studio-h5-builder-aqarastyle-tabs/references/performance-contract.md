# H5 runtime performance contract

Use these budgets as observable acceptance criteria, not as general aspirations.

## Request budgets

- In space mode, Whole-Studio initial load and explicit/pull-to-refresh read device page 1 plus its definitions, in parallel with spaces and manual triggers (normally four requests with one definition batch). Favorites mode publishes device summaries without unrelated first-page definitions (normally three requests); resolve saved favorites first through the shared catalog and definitions for at most 10 selected physical IDs. Publish these entities even while unrelated spaces/scenes are pending; retain existing write/freshness gates.
- After the connected first paint and two render opportunities, the Studio dashboard may start a bounded overview index: one lightweight `GET /devices` catalog request at page size 200 for a 100-device Studio, followed by public definitions for uncached IDs in sequential batches of at most 40 by default. Concurrency is one, refresh/Studio revision cancels stale publication, and the index creates no card DOM. For 100 devices at visible page size 12, the normal full-index budget is eight requests total: four first-paint requests plus one catalog and three background definition batches.
- Each explicit load-more activation appends exactly the next visible UI page. If the overview index already has those models, the activation sends zero requests. If their capability batch is in flight, it joins that same Promise; otherwise it requests only still-missing summaries/definitions. Deduplicate concurrent activations and issue no request while the user merely switches categories, opens device details, or scrolls.
- Keep independent collection reads parallel. Start first-page definitions as soon as page 1 summaries arrive, while spaces/scenes may still be pending. Publish device, space, and scene progress independently instead of waiting for an all-collections barrier. With first-page device time D, definition time F and independent collection time C, the dependency path is `max(D + F, C)`, not `max(D, C) + F`. This is a dependency model, not a measured latency promise.
- Selected-device scope is the deliberate exception: because the public summary route has no exact-ID lookup, it may scan sequential pages only until the requested runtime `did` is found or pagination is exhausted, then fetch definitions for that device.
- A writable trait action sends exactly one `POST /devices/trait/execute`. After the configured delay (default 2000 ms), it may send exactly one `POST /devices/trait/read` for the same device, endpoint, function, and trait. It must not refresh device lists, spaces, scenes, capabilities, or definitions.
- Primary and secondary model-derived Trait controls have the same request budget. Opening/closing the local device-details sheet sends zero requests; all capability rendering must reuse public definitions already fetched by initial load, overview work, or explicit refresh.
- A command action sends exactly one `POST /devices/command/execute`. A scene action sends exactly one `POST /scenes/execute` for a returned sceneId, otherwise one legacy `/automations/manual-triggers/execute` for a complete returned manual pair; never retry/fall back after a write. Neither action triggers an automatic read or collection refresh.
- An advertised native dashboard data subscription forwards only H5-registered device/endpoint/function/Trait coordinates, then applies valid matching pushes to loaded point models and existing cards/space summaries with zero Studio requests. Replace the per-page watch set as definitions, later pages and overview/favorite indexes settle; never send an all-device WebView stream or create a second backend subscription. Typed subscription ACKs do not invalidate collections: after initial loading and only while Home remains active, they may cause one debounced, cooldown-limited Trait read for at most 24 current devices and 96 endpoint/function groups, split into batches of 32. Leaving Home cancels a pending ACK read; an ACK received on another Tab does not make Home dirty. Typed space/automation object events refresh only the affected collection, without disabling scene cards. True push recovery and untyped legacy collection events retain coalesced full Home refresh. Defer during a write/refresh and when Home is hidden. Do not turn high-frequency Trait events into device-list/definition scans, alter the one-write/readback budget, or claim unsupported device add/remove events are live.
- A plain foreground return with the same Studio and a fresh, live snapshot preserves mounted Home content and only schedules the existing bounded Trait reconciliation, prioritizing rendered favorite devices. Coalesce native and DOM visibility reports and defer Home-only work while another Tab is active. A cached/expired snapshot, Studio identity change, an offline return followed by phone-network recovery, true subscription recovery or BFCache document restoration still uses the full refresh path. Never make visibility alone invalidate all collections, disturb an active write/refresh, or change explicit pull-refresh behavior. The snapshot expiry uses the configured cache TTL (default five minutes); the bounded reconciliation retains its cooldown and request caps. Run `smoke_test_foreground_resume.mjs <runtime>` and `smoke_test_dashboard_collection_gate.mjs <runtime>` when maintaining this policy.
- Never retry a write automatically, including on timeout or an ambiguous transport failure. Do not add background polling. Read retries, if later introduced, must be explicitly bounded, honor server throttling, and stay outside direct-action request budgets.
- Camera live is the sole bounded polling exception: after a user starts a definition-confirmed stream, native subscribes before sending one Offer command and performs one targeted signaling-trait read per second only while that Offer is pending, for at most 30 seconds. Stop polling immediately on Answer, failure, cancellation, background, replacement or close. Pause/continue sends no Studio request. At most one camera session may exist per page.

## Tab-aware P0 read plan

- Derive optional work from `config.tabs`, not a presumed three-tab layout. Home-only has no directory prefetch; Home+Devices may prefetch only device page 1; Home+Smart only manual triggers and automation page 1; all three may prefetch both. The current Home template still needs devices, spaces and scenes for overview, AI, favorites and Space control even when those optional tabs do not exist. Module order is not an enable/disable flag; do not invent one or remove required Home reads merely because a Tab is absent.
- Saved favorite definitions may start as soon as fresh device summaries and native identity are available, without waiting for unrelated spaces/scenes. After two render opportunities, join that priority work and schedule a sequential optional-page prefetch alongside the existing bounded overview. Prefetch only page 1, never full pagination/definitions or hidden card/row DOM. Stop dispatching optional tasks when hidden, another tab is active, scope changes, or a user operation owns priority. Entering a tab joins the same read; fresh fulfilled results avoid another native request. Foreground retry remains available after prefetch failure. Overview-disabled packages still support optional-page prefetch; unknown Studio identity skips fulfilled caching and speculative prefetch.
- `StudioRuntime.readCollection` owns a page-local 30-second, maximum-32-entry cache and in-flight sharing for GET `/devices`, `/spaces`, `/scenes` and `/automations`. Use actual native Studio/user identity; the initial page's in-flight reads may join before first identity confirmation, but fulfilled cache entries require a confirmed identity. Subsequent identity changes clear entries and reject late old-scope reads. API base/mode, sorted complete query parameters, paging size/number, keyword and filters distinguish requests. Return separate copies to consumers. Do not infer a complete 200-row page from a 12-row result.
- Failures/malformed collection results are not cached. Explicit Home/page refresh invalidates relevant list entries; favorite return/selector freshness invalidates device summaries; accepted automation updates invalidate automation and scene lists. Cancelled/obsolete flights cannot repopulate replaced entries. Definitions, writes, trait readback and camera signaling never use this list cache. Persistent snapshot caching and its disabled-write behavior remain separate.
- Favorite resolution must not wait for the whole overview definition index. It may join an in-flight lightweight catalog and existing exact definition work. Reuse normalized entities and preserve revision/transaction guards; optional prefetch cannot mark capability state as fresh or enable cached controls.
- Run `smoke_test_read_plan.mjs <preview-workspace>/runtime` plus the four-combination browser gate. Verify query/scope isolation, cloned results, TTL, failed/late reads, selected definitions before unrelated work, slow independent scenes, shared catalog, zero hidden rows and no extra first-entry requests. Keep the original space-mode loading and one-write/one-read regression gates.

## Interaction and state

- Update the exact trait control optimistically at interaction time. Keep only that control busy until the write response, then release it immediately. The delayed readback is asynchronous with respect to the rest of the dashboard; it must not set a page-wide or card-wide busy state.
- A bounded range emits no request for `input` frames. Track active pointer/touch/mouse/keyboard adjustment, commit one changed numeric value only when the adjustment successfully ends, and deduplicate overlapping release/`change` events. Cancellation restores the confirmed preview and emits no write. The commit then uses the ordinary one-write/one-targeted-read budget.
- If the readback equals the optimistic value, perform no visible DOM mutation and show no success toast. If it disagrees, update only the exact existing control, state text, and attributes with the actual value and a local not-applied message; do not replace the card node. If a readback after an accepted write fails, retain the optimistic value with a local unconfirmed message; do not infer that the write failed or fall back to a heavier read.
- On a definite write failure, issue one immediate targeted read for the exact trait. Reconcile from that value when available; only if it also fails restore the last confirmed value. Inspect operation-specific failure arrays in addition to the top-level response code. Use a monotonically increasing per-control revision so an older delayed or failure read cannot overwrite a newer user action.
- Cached partial snapshots may render immediately, but cached controls stay disabled until fresh public definitions for page 1 arrive. Initial load and explicit refresh revalidate page 1; explicitly loaded later pages are cached as part of the current session snapshot.
- Device and scene actions must not call collection renderers or replace collection/card nodes. Matching/mismatched readback and rollback update the existing operated card in place. Sibling node identity, filters, pagination, focus, grid geometry, and scroll coordinates remain stable.
- Collection-level DOM replacement must preserve a semantic viewport anchor. Category changes anchor the existing filter bar, UI-page append anchors the previous last card, and language/refresh rerenders anchor the currently visible card. Disable native overflow anchoring for the managed grid/load-more region, correct the rectangle delta immediately and on bounded follow-up frames, and invalidate stale restoration work when a newer layout begins.
- Separate temporary anti-clamping space from measured card content. Key the latest measured child-content height by category, actual rendered count, available width/columns, and locale; clear it on a fresh snapshot, bound entries (template: 32), and invalidate other geometry changes. The value is a short-lived anchor aid, not a persistent height floor: never keep a historical maximum, never measure outgoing DOM under incoming filter/page state, never cache `min-height` as content height, and remove the inline `min-height` after at most two settled animation frames. A shorter category must then shrink to its real cards, even when the document consequently clamps to its natural end. Release temporary space before a visible load-more control settles so the control follows the last card at its ordinary margin. Once content is rendered, explicit refresh keeps it mounted; skeleton replacement is initial-load-only.

## Payload and rendering

- Use public `/devices/definitions`, not the larger internal full-definition endpoint. Request only the IDs from the newly loaded backend page (or the selected device) and batch within the documented 200-ID limit; prefer a smaller configurable batch to avoid oversized URLs.
- Keep normalized view models and discard unused response fields. Render visible page 1, then append each later visible page only after its explicit load-more action. The overview index may retrieve lightweight summaries and normalized capabilities after first paint, but it must not create hidden DOM cards; mounted card count remains controlled by the user-visible pagination.
- Space control reuses its capability model and observation index while their inputs are unchanged. Build category/room membership and counts once per changed index, including nested-room membership; keep direct-room counts distinct from descendant-inclusive filtering. The detail sheet initially mounts at most 20 cards and appends 20 on request. On status/readback changes, update the existing card nodes and summary values without clearing the detail grid or moving scroll/focus. Full collection replacement is reserved for membership/order changes, locale changes and a changed Studio scope.
- Preserve every safely renderable operational control and useful presentation reading in the normalized model. Mount primary and verified high-frequency category controls initially; create only residual controls/readings on first sheet open using the latest model values and current busy/cache permissions. Reparent and reuse those nodes on close/reopen instead of cloning them. Pending and readback reconciliation must query both the card and active sheet. Stop the sheet layer's touch/pointer/wheel propagation before document-level pull/scroll handlers; keep only the content pane vertically scrollable with contained overscroll. Hidden residual count must not determine card size. This must not remove any capability or issue a request.
- Explicit backend pagination appends only the newly fetched page using a fragment and preserves all existing card nodes, expanded state, focus and pending controls. Collection replacement is still valid for snapshot/category/language changes. Keep a device-ID-to-mounted-card Map for local reconciliation and clear it whenever the grid is replaced; do not retain detached cards in a global cache.
- Keep local, dependency-free assets and avoid runtime compilation, CDNs, service workers, and recurring timers.
- Camera WebRTC code stays in three small local assets. Do not initialize a PeerConnection, native subscription, timer or media element stream until the user presses the live-view button. Collection replacement and page lifecycle must release all of them.

## Layout and main-thread work

- Do not add masonry to ordinary grid output for performance reasons. For requested masonry, batch width preparation, then all card-height reads, then placement writes. Avoid `write gridColumn -> read rectangle -> write gridRow` for every card. Measure at the correct ordinary/full-span width, and invalidate measurements after width, font, locale, disclosure, or content changes. Do not reuse a measurement merely because the device ID is unchanged.
- Coalesce responsive relayout to one scheduled frame; invalidate stale work. Do not relayout for a device acknowledgement when its geometry has not changed. Keep anchor repair bounded and outside the per-card loop.
- Preserve the user's chosen appearance. Avoid adding blur to every tile, permanent `will-change`, animating dimensions, or new full-page decorative layers. Inspect compositor/paint cost on the minimum supported phone before changing existing glass styling. Do not introduce `content-visibility`, containment, virtual scrolling, or workers without proving iOS-baseline compatibility, focus/disclosure behavior, and viewport stability.
- Pagination controls DOM growth by user demand; it does not make a fully loaded 1,000-device DOM constant-sized. Measure that case if it is in scope. Virtualization is a separately tested architecture choice, not an automatic retrofit.

## Memory and cache accounting

- Normalized models are the shared state. `controls`, primary `control`, `readings`, and `presentationReadings` may share objects in memory; JSON serialization duplicates those references. Measure the serialized snapshot separately from JS heap and DOM count.
- Keep cache-first display, TTL, disabled cached controls, and storage failure fallback intact. Current sessionStorage serialization/parsing is synchronous. If traces show it blocks first paint, move serialization after a render opportunity with a bounded idle/timer fallback; test refresh ordering, page lifecycle and storage failure before shipping that change. Compact snapshots require explicit rehydration and cache-version tests; never solve a memory target by silently dropping real capabilities, devices, or cached functionality.
- The current native API does not expose a stable Studio cache namespace in this contract. Do not request credentials or derive a namespace from a token as a performance shortcut.
- Bridge callback pairs/timers must settle and release on success, error and timeout. Document-lifetime language/theme listeners are acceptable for this single-page package. If a future SPA mounts/unmounts dashboards, dispose listeners/observers/frames and suppress stale callbacks; do not impose an untested pagehide cancellation on already accepted writes or BFCache restoration.

## Measurement and release gates

All gates follow the no-automatic-installation rule in SKILL.md. Use existing Playwright Node/browser paths or existing platform browser capabilities; never install pip/npm packages, browsers or drivers to run these checks. If prerequisites are unavailable, continue other executable checks and explicitly report this gate as not run. An available gate that fails still requires investigation.

- Run `node scripts/profile_h5.mjs <package> --platform ios [--playwright-module <installed-module-entry>] [--browser <browser-executable>]` and repeat with `--platform android` when DOM, rendering, loading, or host integration changes. The iOS fixture injects `window.webkit.messageHandlers.nativeBridge`; the Android fixture uses an Android UA/touch context and routes the same full-dashboard workload through `window.prompt(method, paramsJson)`. Both use synthetic data only in the test environment. If browser tooling is unavailable, disclose the missing gate; do not add it to the production package or present Chromium emulation as real-device proof.
- `--baseline` collects a comparison from an older package without enforcing the newly introduced lazy-mount/append requirements. Use the same fixture, browser, viewport and device. The script checks first-page-only startup, exact click-to-page request pairs, lazy device-detail mounting, retained pagination nodes, bounded mounted DOM over repeated presentation cycles, zero-request sheet actions, unchanged card/neighbor geometry, silent successful readback, definite-failure reconciliation, and the one-write/one-read contract.
- Report static bytes, normalized/cache sizes, first connected render, DOM/control counts, long tasks, append/switch timings, request sequence/concurrency, and viewport deltas. Separate native/network wait, normalization, DOM creation, layout, and storage in deeper profiling. Do not include fixture devices or timing instrumentation in production output by default.
- A task over 50 ms is a profiling trigger. Target prompt feedback within the next rendered frame and no interaction task over 50 ms on the agreed minimum phone; quantify p50/p95 with repeated traces before claiming that target is met. Desktop fixtures cannot establish Life WKWebView latency or physical-device response SLAs.
- Stable DOM counts are not a heap-leak proof. For memory-sensitive releases compare retained heap/detached nodes after repeated cycles and settled callbacks, plus WebKit process memory on device. Chromium `performance.memory` is optional/coarse and is not portable iOS evidence.

## Verification

Automated smoke tests must record native requests and prove all of the following:

1. space-mode first paint requests only device page 1 and its definitions (favorites mode uses the priority plan above); the bounded post-paint overview index uses one lightweight catalog scan plus sequential definition batches at concurrency one, mounts no cards, and publishes explicit coverage;
2. a load-more action exposes exactly one visible page and reuses ready/in-flight overview models without duplicate network requests;
3. only public resource paths are used;
4. one trait action causes exactly one write and one targeted read, with no collection or definition request after the write;
5. Boolean and numeric writes retain their JSON types;
6. a top-level success containing a failure item is rejected;
7. commands and scenes cause one write each with no automatic follow-up;
8. unknown zero-field commands remain read-only.
9. a multi-capability device retains all safe returned controls while excluding configuration/metadata Traits from the operational surface;
10. a secondary Trait action still produces exactly one write and one targeted readback, with no collection request.
11. multiple range `input` events plus an early `change` during an active drag produce zero requests; successful release produces one write, followed by one delayed targeted readback.
12. sparse category switch/back, device-details open/close, UI-page append, device/scene action, delayed readback, rendered-content refresh, and host-language change preserve the relevant semantic viewport anchor; direct actions and the sheet do not replace collection nodes or change grid geometry.
13. first-page definitions and device rendering complete while deliberately delayed spaces/scenes remain pending, without blocking on the overview index.
14. an accepted matching readback causes no visible DOM mutation or success toast; a definite write failure triggers one immediate targeted read and corrects only the exact control, with stale readbacks rejected by revision.

## Favorite Home mode

Reuse the existing overview/capability index, without another launch scan. Only explicit selection-page open can complete the shared index (sequential/coalesced and bounded at 5000 devices). Mount 200 selection rows initially, append explicitly, and at most 10 Home endpoint cards. Room filters issue zero requests. Shortcuts issue one exact write and at most one targeted read pass, without optimistic guessed state or collection refresh; failed writes require user retry. Validate rich-card DOM/gesture/camera budgets on a default space-mode regression package and Favorite geometry/selection/action on the module browser gate.

Persisted choices outside the bounded initial index are resolved after overview settles: reuse catalog pages, scan only further lightweight device pages until the missing saved IDs are found (maximum 5000 devices), and request definitions for at most those 10 selected devices. Coalesce work and guard revisions; do not index unrelated capabilities, mount hidden cards or expand the global overview limit. A missing/deleted endpoint remains a removable unavailable choice; refresh allows retry.

Favorite native return performs coalesced fresh selected-device reconciliation (selection saves issue only metadata requests; unchanged/removal/known-addition commits issue zero entity requests): sequential lightweight catalog pages until saved IDs are found (5000 bound), fresh definitions for at most 10 devices, no scene/space refresh, no writes and no polling. Cached index resolution is not sufficient after editing in a native plugin. Per-device write pending, failed refresh and unknown connectivity gate affected shortcuts; background collection reads never disable the whole grid. See favorite-devices-contract.md for request ordering, stale-data and selector freshness rules.

## Overview connectivity count

Online-device count comes from device-list summaries, independently of definition indexing. Use the first loaded list before the overview catalog resolves; then count the deduplicated overview lookup catalog, including summaries whose definitions are pending/failed. Definition batches only expand capability/environment coverage and must never overwrite connectivity count with the number of resolved favorites or indexed models. Mark the overview count source as `device-list`; older cached capability-derived counts are not authoritative. On catalog failure retain the current loaded-list count. Do not use a permanent maximum or suppress actual decreases after a new device-list refresh; do not add requests for this display fix.

Favorite metadata scheduling and persistence follow favorite-metadata-contract.md. Start the shared query independently of scene/device lists, request only enabled Home favorite keys, and preserve the existing P0 collection cache and device control budgets. A POST metadata query is a read, not a device write.

### Definition failure recovery

Only returned device IDs are cached as capability models; an omitted definition stays unresolved and contributes to partial coverage. A catalog failure settles the automatic-device loading state as unavailable. A native definitions read explicitly rejected with `Replay request is rejected` may be reissued once through the existing bridge, only while the load revision and collection epoch still match. Do not replay device writes, scenes or metadata saves, alter signing headers, or infer that this recovery proves the native rejection cause. `smoke_test_role_loading.mjs` covers the five audiences and failure paths; use it in maintenance alongside affected UI checks.
