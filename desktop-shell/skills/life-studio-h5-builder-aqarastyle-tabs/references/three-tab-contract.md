# Three-tab contract

Devices/Smart page presentation and search/filter behavior follow [directory-figma-contract.md](directory-figma-contract.md), snapshot `20564:9469`. This later contract supersedes the historical combined-group and inline-search layout below.

## Scope and boundaries

Default `--scope studio` and `--tabs home`. Configurable bottom tabs with local inline SVG icons and labels: 首页/Home, 设备/Devices, 智能/Smart. Home is the bundled stable dashboard, including the camera session provider, readiness, and WebRTC runtime. These three camera files must remain unchanged when editing tab navigation. The original builder is historical provenance only, never a generation dependency. The package requires no application checkout or another skill.

The new modules are `studio-tabs-runtime.js` (bridge requests and plugin navigation), `studio-tabs.js` (state and safe text DOM), and `tabs.css`. `dashboard.js` owns one shared `StudioPullRefresh` controller; directories register their existing refresh and busy callbacks, and tab changes cancel the current gesture. Pull refresh translates a dedicated `.pull-refresh-content` wrapper with bounded resistance (up to 60px), holds at 44px during the request and settles back on completion or cancellation. `#app`, fixed tabs and overlays never translate; no layout spacers or persistent scroll offsets are added. The top indicator is progressively exposed in the revealed zone at `calc(8px + var(--safe-top))` in every tab. Device navigation rows and non-control card surfaces can start a vertical pull while retaining normal taps; continuous controls, horizontal/nested scrollers and modal layers retain their gestures. Verify list text origins, a 59px safe area, fixed tab geometry and the complete settle. Preserve the home-tab guards for viewport anchor restoration and resize layout. Hidden home work must not move the directory viewport. Switching away from Home closes the capability sheet and stops live camera sessions via its public lifecycle API. Return preserves the home DOM and scroll; restarting video is explicit. No camera transport changes.

## Real data

All new requests use `LifeBridge.nativeHttpRequest`, GET, `modeType: sdkMode`, `headers: { source: 'studio' }`, with the configured API prefix. Host owns credentials and current Studio selection. Never copy example IDs, synthesize records or put test fixtures into production runtime assets. Optional canvas preview fixtures are isolated under preview/ as documented in the canvas preview contract. A plain browser without the native bridge shows unavailable/error states.

- Devices: `/open/api/v1/devices`, pageNum starting at 1, pageSize 200. Envelope `code:0,data:{data:[],totalCount,pageNum,pageSize}`. Read `deviceId`, `deviceName`, `deviceTypesList`, `state`, `space.spaceId/name`. Group by space ID, never display name. Same-named spaces remain separate. Missing assignment has a separate group. `/spaces` returns the nested tree `spaceId,name,children` for breadcrumb labels. If that request fails, still display device assignments and an explicit warning.
- Scenes: `/open/api/v1/scenes`, `pageNum`, `pageSize:200`, `needChildren:true`. Share the Home/selection parser and collection reads. Use the RN-compatible identity, title, Boolean normalization and execution rules in [favorite-scenes-contract.md](favorite-scenes-contract.md); include disabled scenes.
- Automations: `/open/api/v1/automations`, `pageNum`, `pageSize:200`, `orderBy:'createTime asc'`. Same paged envelope; `automationId,name,enabled,space`. Display all definitions returned by the route; do not discard ones with manualTriggers or assume an undocumented definition type. Two separate segment panels: Scenes first by default, then Automations; only one is visible. Scenes display status; each automation has an enable/disable switch. Home keeps its existing scene execution behavior.

Directories are lazy on first selection. Returning to a loaded tab does not refetch. Returning to Home also keeps its loaded snapshot: apply retained bounded Trait pushes and scoped object changes without a full request wave. Only a true session recovery, Studio identity change, explicit refresh or native-page return may initiate a full Home reload. An automation toggle may refresh the Home scene collection alone. The Home header with its Mine entry is visible only on Home; no tab has a top-right refresh button. Devices and Automation begin with their own page heading, with no Home title or top navigation. Pull-to-refresh updates the active directory; retries and pagination remain available. Paginated lists retain previous rows on a failed next page and retry the same page. Display Load more until totalCount is reached or a short page proves completion when count is absent; no fixed record ceiling. Each automation group can fail/retry independently. Never present failed requests as empty lists. No cross-session persistent directory cache. User-visible status is unknown for missing values.

If a Home collection request completes after the user switches tabs, retain its scoped result and render it only when Home becomes active. A later full refresh or Studio identity change discards that result. Repeated unchanged Reachable pushes must not rebuild camera cards; actual online transitions still update camera availability without a full collection read.

## Plugin bridge integration (optional host capability)

Capability: `openDevicePlugin`; request `{deviceId: string,deviceName: string}` via `LifeBridge.invoke`. Values come from the clicked API record. No arbitrary native route or plugin URL. Host validates nonempty ID and account/Studio lease, then calls its existing device plugin resolver. Capability must be advertised only where implemented; host capability registration and method dispatch should share the same identifier. Response `{code:0,data:{accepted:true}}` acknowledges routing; it does not prove the plugin was presented. Native routing failures are handled by the existing host resolver. Hosts explicitly advertising a capability list without this method keep lists visible and show an update-required message. An absent/empty capability list is a legacy unknown state: follow LifeBridge.supports and attempt this navigation once, requiring the normal accepted acknowledgement. Do not bypass an explicit unsupported declaration or invent plugin URLs. Rerender on the native-context-ready event so late metadata does not leave a stale banner.

Reference integration in Aqara Life: add capability in the native context factory; handle it in the custom bridge delegate using a retained existing navigation handler (async callbacks use weak self). These are integration examples, not source paths required for skill use. Never implement plugin fetching or credentials in H5. Validate actual plugin presentation on device separately.

## UI / verification

Float a rounded translucent tab bar above bottom safe area, use backdrop blur and a selected capsule, provide opaque fallback and dark/reduced-motion/reduced-transparency states. Reserve bottom padding for content and toast; sheets stay above navigation. Minimum touch height 44px. Use tablist/tab/tabpanel semantics, hidden inactive panels, aria-selected/aria-controls, roving tabindex and Arrow/Home/End navigation. Support zh-CN, zh-TW, en. Smart scene execution failures use the same localized “操作失败，请重试” message as Home Favorite scenes; automation switch errors retain their own message. Preserve tab scroll positions. Escape API strings by using textContent, never API HTML.

Run `validate_h5`, `validate_aqara_style`, `smoke_test_h5`, `smoke_test_tabs`, `validate_portability`; then `profile_h5` for Home and `profile_tab_combinations` for all four navigation combinations. For three-page packages also run `profile_tabs_h5` for directory and switch interactions. Inspect screenshots on 390px light and 320px dark and Android. Fixtures must test pagination, identical space names, unassigned devices, disabled/missing status, exact clicked bridge IDs, unsupported capability, per-group failures/retries, warm tab switches, keyboard navigation and no horizontal overflow. Browser QA is simulated API/bridge verification. Real account data, plugin presentation and camera LAN/remote continuity require user device verification; report them as pending unless actually observed.

Automation switches: `POST /open/api/v1/automations/status`, body `{automationIds:[automationId],enabled:boolean}`. Require `code:0` and requested ID in `data.successIds`; an empty/partial success array is failure. One write per tap, no retry, no guessed IDs. Lock only the pending row and block automation-list refresh until writes settle. Keep previous state on failure and show a localized error. `--read-only` disables switches via `enableAutomationWrites:false`; unknown status is disabled. On success update related scene rows in memory and refresh Home on its next activation to invalidate stale scene availability. Verify enable, disable, empty-success rejection, failed-write rollback and double-tap suppression in browser QA.

Clean App deliverable: production packages contain only the H5 runtime and documented packaging assets. Optional canvas workspaces follow [canvas-preview-contract.md](canvas-preview-contract.md) and keep mock resources in preview/, excluded by the App export allowlist. Store QA screenshots, test reports, logs, fixtures and profiling results outside the package directory (including descendants). Use a separate caller-selected QA directory. Both browser profilers reject screenshot destinations inside the package; validate_h5 rejects known QA directories and verification artifacts. Never copy QA output back into the deliverable.

## Page combinations

Generator `--tabs` accepts `home`, `home,devices`, `home,automation`, or `home,devices,automation`. Home is required; duplicate/unknown IDs and missing Home are invalid. Optional pages use canonical Home/Devices/Automation order. `config.tabs` stores stable page IDs, never labels. Derive the number of columns and keyboard wrap from enabled pages. Single Home mode hides navigation before JavaScript runs and preserves the original home bottom spacing and toast position. Disabled panels and tab buttons are omitted from generated HTML and do not request their APIs. In particular Home-only and Home+Devices never read `/automations` for the automation directory; Home retains its existing /scenes reads. Generated files remain self-contained and clean in all four combinations.

Map the user's requested page names to `--tabs` automatically. When page selection is unspecified, use the selected role profile: unspecified role/AI default and male have three pages, female has Home + Devices, senior/child have Home only. Do not ask merely to choose a count. Verify all four combinations, including Home+Automation label/keyboard mapping, omitted-page requests, and no single-page footer gap. Existing artifacts retain their confirmed page selection when updated.

The reference native implementation reuses one retained HomepageHandler. Both native homepage cell taps (with context) and H5 clicks (with an API device ID resolved into context) converge on openDevicePlugin(for:). This shared entry retains installed-plugin/native-page fast paths and plugin-marketplace fallback. H5 cannot add a missing native implementation: the app must be built with the registered custom method before claiming real device navigation is supported.

## Navigation labels and Home spaces

The third tab is labeled 智能 / Smart (zh-TW: 智能); keep `automation` as its config/DOM identifier for compatibility. Scenes and Automations retain their own group labels and switch semantics. Home uses space chips instead of category chips: the single outermost space uses its API name and selects all loaded devices (including root-assigned and child-space devices), each actual Studio space ID selects its assigned loaded devices, and missing assignments use a localized Unassigned chip. Include the existing snapshot space tree flattened by the runtime, even empty spaces; supplement with device assignments when space metadata is unavailable. Same-named spaces must remain distinct by ID. Preserve root metadata when flattening the tree and render the outermost space once, as the all-spaces entry. If the root is unavailable or there are multiple top-level spaces, use the localized All fallback; do not guess the root by name or array position. Older cached snapshots without root metadata use the fallback until refreshed. Filtering is local, introduces no requests and keeps progressive pagination; do not fetch the complete device catalog just to filter. For a space with no currently loaded devices while pages remain, explain that more may be loaded rather than claiming the space is empty. Preserve selection through locale changes and pagination. Localize navigation, filter accessibility and empty states in zh-CN, zh-TW and en; never translate server-owned device or space names.

## Loading position and glass navigation

Keep Home at scrollY=0 through initial scene/device/overview loading in both canvas preview and App. At the document start, use the page-origin anchor rather than anchoring the lower device/filter section whose position changes when data arrives. Capture refresh anchors immediately before applying an asynchronous response, not before waiting for network data, so scrolling during the wait retains the user's current reading position. Preserve existing visible-card/filter anchoring after the user scrolls. Never mask layout shifts with delayed unconditional scrollTo(0,0). Browser gates must assert no initial scroll events above 1px through overview completion, and retain existing filter, sheet and write-position checks.

Bottom navigation follows a web adaptation of Apple's Regular Liquid Glass navigation material: one floating neutral surface, visible content color beneath, a restrained curved highlight/rim and soft shadow. Use one backdrop blur/saturation surface only; do not simulate a second glass layer on the selected button. Selection uses a neutral translucent fill and accent symbols/text. Move the shared selection indicator with a bounded transform transition; preserve tab geometry, safe areas, keyboard focus and touch targets. Avoid heavy blue/white gradients, opaque-looking selected capsules, neon rims, animated filters, content duplication for fake refraction, canvas capture or continuous scroll sampling. Current backdrop filtering responds to underlying content; native real-time lensing, environment lighting and automatic luminance-based material changes are not implemented by this CSS approximation. Provide opaque fallback when neither backdrop property is available, and honor reduced transparency/motion and increased contrast. Keep the bundled implementation self-contained; these official links are design provenance, not generation-time dependencies.

Official references reviewed for this material adaptation:
- [Apple HIG — Materials](https://developer.apple.com/design/human-interface-guidelines/materials): navigation/content layering and material legibility.
- [Apple HIG — Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars): floating navigation, icons/labels and content peeking beneath.
- [WWDC25 — Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/): lensing, neutral Regular material, avoiding glass-on-glass, selective tint and accessibility. These native properties inform the adaptation; they are not claims of web parity.
